# Islamic Salafi Skill + Adab Persona — Multi-Platform & Open Contribution Design

Date: 2026-10-17
Status: Approved by owner 2026-10-17

## Intent

The skill was generated by OpenClaw ~7 months ago and has not been touched since. The owner wants it to become a maintained, community project: other people contribute, and the same skill works across Claude Code, Codex, OpenClaw, Hermes, and ChatGPT.

The question "convert to a Claude plugin or something else?" resolves to: **don't convert — keep one Agent Skills–standard folder as the single source, and add thin delivery wrappers around it.** All target tools already read `SKILL.md`.

## Goals

1. One source of truth for the skill content; every platform consumes it without a hand-maintained copy.
2. Contributors can open PRs, and every PR is automatically checked for format/syntax.
3. Skill prompt is rewritten to current best practice so it behaves well on both Claude and GPT-5.x models.
4. An LLM prompt-quality review runs on PRs from same-repo branches (see CI).
5. A small behavioral eval suite catches regressions in how the skill answers.
6. A separate, always-on **Islamic adab persona** (how the agent speaks in every session, not fiqh): one markdown file anyone can copy-paste or append with a one-liner, and contribute to. See "Adab persona".

## Non-goals

- Changing any religious ruling, scholar position, or madhab methodology. The rewrite touches structure and wording only.
- Automated verification of religious correctness (hadith grading, fatwa attribution). A bot cannot do this; it stays with the human maintainer.
- Publishing to ClawHub / Hermes Skills Hub / OpenAI plugin directory in this round. The layout should make that cheap later, nothing more.
- A website, docs site, or any runtime code.

## Anti-goals (would be a failure even if it technically works)

- The skill confidently emitting fabricated fatwa numbers, URLs, or hadith numbers. The current skill actively encourages this (see "Prompt rewrite").
- Platform copies drifting apart (e.g. a hand-edited ChatGPT version that goes stale like the original did).
- CI that leaks the repo's API key to fork PRs.

## Current state (as found)

```
SKILL.md              252 lines, ~14 KB; name: islamic-salafi
references/aqeedah.md, fiqh-ibadah.md, muamalah.md, tazkiyah.md   (~20 KB total)
README.md             OpenClaw-only install docs
.gitignore            (no LICENSE, no CONTRIBUTING, no CI)
```

Problems found in review:
- **Spec violation:** agentskills.io requires `name` to match the folder name. Repo folder is `skill-islamic-salafi`, name is `islamic-salafi`.
- **Fabrication pressure:** "Every ruling MUST include … fatwa no. XXXX / URL", plus examples with specific islamqa numbers, teaches the model to invent identifiers it can't verify.
- **Over-emphasis:** ALL-CAPS headers and MUST/Always/Never throughout. Both Anthropic and OpenAI guidance now say this causes over-triggering; reserve it for true invariants.
- **Self-contradiction:** "Always use the 3-part format" vs. examples that use different headings (Shafi'i layered case).
- **Time-sensitive content in the core prompt:** scholar "Active" status table, site lists. These go stale and belong in a reference file contributors can update.
- Odd scope line: "Fiqh opinions that conflict with both the Shafi'i madhab and established Salafi scholarship" — wording to be clarified, meaning preserved.

## Decisions

### Repo layout (decided)

```
.claude-plugin/
  plugin.json             name, description, author, license (no version)
  marketplace.json        repo is its own marketplace; plugin source "."
skills/islamic-salafi/
  SKILL.md                rewritten; body ≤ 8,000 chars (see ChatGPT)
  references/
    aqeedah.md  fiqh-ibadah.md  muamalah.md  tazkiyah.md   (moved, content unchanged except TODO marks)
    sources.md            NEW: scholar/site/classical-text tables moved out of SKILL.md
    examples.md           NEW: worked bilingual examples moved out of SKILL.md
chatgpt/                  GENERATED, committed (see ChatGPT)
  instructions.md
  knowledge.md
scripts/build-chatgpt.sh
evals/                    claude plugin eval cases
.github/workflows/        ci.yml (format), review.yml (LLM review), eval.yml
.github/pull_request_template.md
CONTRIBUTING.md
README.md                 rewritten: per-platform install
```

Moving the skill into `skills/islamic-salafi/` fixes the name/folder mismatch and is the Claude plugin default layout.

### Per-platform delivery (decided)

| Platform | Mechanism | Repo work |
|---|---|---|
| Claude Code | Plugin + marketplace: `claude plugin marketplace add rhapsodixx/skill-islamic-salafi` then `claude plugin install islamic-salafi@<marketplace-name>` | two JSON files |
| Codex | Reads `.agents/skills/` (repo) or `~/.agents/skills/` (user); `$skill-installer` | README instructions only |
| OpenClaw | `openclaw skills install git:rhapsodixx/skill-islamic-salafi@main` or copy to `~/.agents/skills` | README only |
| Hermes | `hermes skills install <raw SKILL.md url>` or `hermes skills tap add rhapsodixx/skill-islamic-salafi` | README only |
| ChatGPT Business/Enterprise/Edu | Native Skills (beta, admin-enabled): upload the skill folder as zip | README only |
| ChatGPT Free/Plus | Project: paste `chatgpt/instructions.md` into project instructions, upload `chatgpt/knowledge.md` | build script |

Builder: verify each README install command against current docs before writing it; the research behind this table is from 2026-10-17 and some ChatGPT limits came from third-party sources.

### ChatGPT Project bundle (decided; mechanism is my call)

- Limits: project instructions ~8,000 chars; Free plan allows 5 project files.
- Approach: make the rewritten `SKILL.md` body itself fit under 8,000 chars (moving sources and examples out gets it there). Then the build is mechanical, no LLM summarization:
  - `instructions.md` = SKILL.md body with frontmatter stripped, plus one line telling the model the reference material is in the uploaded knowledge file.
  - `knowledge.md` = all `references/*.md` concatenated, each under a heading naming the original file.
- One knowledge file keeps Free users inside the 5-file cap.
- Output is committed (not a release artifact) so users can copy from GitHub directly. CI rebuilds and fails if the committed output differs, and fails if `instructions.md` > 8,000 chars.

### Prompt rewrite rules (decided)

Applies to `SKILL.md` (and the moved-out `sources.md` / `examples.md`). The four existing reference files are moved with content unchanged except `TODO(maintainer)` marks — rewording ~20 KB of religious text is out of scope this round (my call). Content meaning preserved.

1. **Citations:** cite a fatwa number, hadith number, or URL only if it appears in the reference files. Otherwise cite scholar + book/work by name, or use the uncertainty protocol. Remove invented-looking numbers from examples unless they are in references.
2. **Emphasis:** MUST/NEVER only for true invariants — no novel fatwas; grade every cited hadith; stay within scope. Each invariant gets a one-line reason. Everything else in plain imperative.
3. **One response shape** that covers both the simple case and the layered Shafi'i case (e.g. Daleel → Positions (Shafi'i mu'tamad first, stronger daleel if differs) → Practical guidance). Examples must match it.
4. **Format:** Markdown headings; XML tags only to fence examples. Sentence-case headers, no ALL CAPS.
5. **Description:** third person, what + when, keep the Indonesian and English trigger phrases, ≤ 1,024 chars.
6. **Progressive disclosure:** SKILL.md links each reference with a "read when …" line.
7. **Staleness:** anything I suspect is out of date (e.g. scholar "Active" statuses) gets `<!-- TODO(maintainer): verify -->`; I do not change the fact myself.

### CI (decided)

**`ci.yml` — runs on every PR, including forks, no secrets:**
- `skills-ref validate skills/islamic-salafi` (agentskills.io spec)
- `claude plugin validate . --strict`
- JSON validity of manifests; all `references/...` links in SKILL.md resolve
- SKILL.md body ≤ 8,000 chars, ≤ 500 lines; description ≤ 1,024 chars
- `scripts/build-chatgpt.sh` output matches committed `chatgpt/`
- Markdown lint (default ruleset, relaxed line length)

**`review.yml` — LLM prompt-quality review, same-repo branches only (owner decision):**
- Runs on `pull_request` for branches inside the repo; skipped for fork PRs (no secrets there, and no `pull_request_target`). Fork PRs are reviewed by hand, or the maintainer pushes the fork branch into the repo to get the AI review.
- `anthropics/claude-code-action@v1`, read-only + inline comments. Review prompt checks the changed skill text against the rewrite rules above (fabrication pressure, emphasis, contradictions, cross-model wording, token cost). It does not judge religious correctness.

**`eval.yml` — behavioral evals, same-repo PR branches and push to main (same fork rule as review):**
- `claude plugin eval` with pinned model and judge model, `--max-cost-usd` cap.
- Starter cases (~6): no fabricated fatwa numbers; replies in user's language (ID + EN); Shafi'i mu'tamad presented first on a layered question; ends with Wallahu a'lam; declines partisan hizbiyyah question politely; uncertainty protocol on an obscure question.
- Evals cover Claude only. GPT behavior is checked manually by the maintainer (out of scope to automate now).

### Contributor docs (decided)

- `CONTRIBUTING.md`: how to edit, how to run checks locally, what the maintainer reviews by hand (sources).
- PR template: every new/changed ruling or citation must include a source link or book reference the maintainer can check.

## Adab persona

### Intent
The owner's own `~/.claude/CLAUDE.md` has a "Personal Style & Character" section (Bismillah when starting, Wallahu a'lam when unsure, ﷺ, etc., used naturally, no unprompted moralizing). Package that, extended with standard Islamic speech etiquette, so others can install it into Claude Code, Codex, OpenClaw, Hermes, and ChatGPT, and contribute to it.

### Content (decided; exact wording left to builder)
- Restraint rule first: use expressions naturally as a practicing Muslim engineer would; never in every sentence; no religious commentary on purely technical tasks unless asked.
- *Bismillah* when starting a task/session; *Alhamdulillah* on completion or good news; *In sha Allah* for future commitments; *Masha Allah* when genuinely impressed; *Wallahu a'lam* when uncertain.
- Honorifics: ﷺ after the Prophet Muhammad; *'alayhis salam* for other prophets; *radhiyallahu 'anhu/'anha* for Sahabah; *rahimahullah* for deceased scholars; *subhanahu wa ta'ala* for Allah where natural.
- Social: return *salam* properly; *Jazakallahu khairan* when thanked/thanking; *Astaghfirullah* when admitting a mistake; *Barakallahu fik* on someone's good news.
- Islamic questions: answer within Ahlus Sunnah wal Jama'ah, pointing to the islamic-salafi skill where installed. Citation guardrail (my call, follows the fabrication anti-goal since the persona often runs without the skill): name scholar and work only; no fatwa/hadith numbers or URLs unless certain; otherwise say Wallahu a'lam and suggest asking a qualified scholar.
- Voice: plain, calm instructions; MUST/ALWAYS avoided (same rewrite rules as the skill).
- Hard limit: **≤ 1,500 characters for the whole `persona/islamic-adab.md` file, markers included** (my call: that's what users paste) (fits ChatGPT Free custom instructions; both vendors favor short always-on prompts). CI enforces.

### Delivery (owner decision, 2026-10-17): copy-paste markdown only
One file, `persona/islamic-adab.md`. No plugin, hook, or installer script. README has a "Persona" section with, per tool, where to paste it and a readable append one-liner:

| Platform | Paste into | One-liner |
|---|---|---|
| Claude Code | `~/.claude/CLAUDE.md` | `curl -fsSL <raw-url> >> ~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` (never `AGENTS.override.md`, which replaces the user's file) | `curl -fsSL <raw-url> >> ~/.codex/AGENTS.md` |
| OpenClaw | `~/.openclaw/workspace/SOUL.md` (workspace-scoped; no global persona file) | `curl -fsSL <raw-url> >> ~/.openclaw/workspace/SOUL.md` |
| Hermes | `~/.hermes/SOUL.md` (global) | `curl -fsSL <raw-url> >> ~/.hermes/SOUL.md` |
| ChatGPT | Settings → Personalization → Custom instructions, or a Project's instructions | copy-paste only |

`<raw-url>` = `https://raw.githubusercontent.com/rhapsodixx/skill-islamic-salafi/main/persona/islamic-adab.md`.

- The file is wrapped in `<!-- islamic-adab:start -->` / `<!-- islamic-adab:end -->` so users can find, update, or remove it.
- README notes: re-running the one-liner appends a duplicate; to update, replace the block between the markers; to remove, delete it.
- Considered and rejected: an installer shell script (no native install on any tool, `curl | sh` costs trust); a Claude plugin output style (`force-for-plugin` overrides the user's own style); a Claude SessionStart hook (works and is additive, but the owner prefers one copy-paste path everywhere).

### Layout
```
persona/islamic-adab.md       the only persona file
```
- CI adds: file ≤ 1,500 chars; both markers present.
- No automated persona evals (not a plugin). Behavior is checked by hand.

## Constraints

- Secrets: `ANTHROPIC_API_KEY` (or `CLAUDE_CODE_OAUTH_TOKEN`) repo secret for review/eval workflows.
- `.gitignore` currently ignores `dist/` and `.claude/` — `chatgpt/` and `.claude-plugin/` are deliberately named to avoid those.
- Plugin/marketplace names must not start with `claude-`/`anthropic-` or use reserved names.

## Left to the builder

- Exact wording of the rewritten SKILL.md within the rules above.
- Markdown lint tool choice and config.
- Exact eval case prompts and grader wording.
- Marketplace name.
- Plugin `version`: omitted from `plugin.json` so content updates reach users on each commit without a release step (my call).
- Whether to also add `.agents/skills` symlink for in-repo Codex use (nice-to-have).
